## 2. Принципы

- **Harness разрезан на две части.** Harness-0 — минимум для архитектора и критика. Harness-1 — всё остальное; с 27.10 это harness v2 (`docs/harness.md`).
- **Инфраструктура — пилот конвейера.** 2–3 тикета MW проходят полный цикл Jira → ветка → Mac → PR → ревью → статус до того, как конвейер получит настоящий код.
- **В облаке код приложения не пишется**: там нет Xcode, компилировать нечем. Исключение — пакет, тестируемый на Linux, если архитектор его выделит (§4 п. 2).
- **Точки Edward** — по harness §5: развилки, аппрув PR (auto-merge), проверка на устройстве, релиз. Стоп «перед коммитом» снят 27.10.
- **Одна сессия = одна роль или один тикет.** Документы читаются по таблице чтения продукта §0, а не целиком.
- **Решение без записи в `docs/` не принято.**

## 3. Состояние репозитория (13.10.2026)

- Xcode 27.0, Swift 6.4, языковой режим Swift 6 (`SWIFT_VERSION = 6.0`; режимов 6.x не существует), minimum iOS 17.0. Приложение и тест-таргеты собираются, юнит-тест проходит.
- Шаблон Xcode включил `SWIFT_APPROACHABLE_CONCURRENCY = YES` и `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`. У тест-таргетов включён только первый. Осознанно это никто не выбирал — вопрос архитектору (§4 п. 1).
- `.claude/skills/swiftui-pro/` — SwiftUI Pro (Paul Hudson, MIT, v2.0.0). Версия зафиксирована коммитом, работает на Mac и в облаке. **Скилл считает базой iOS 27, у нас iOS 17**: новые API — только через `#available` с фолбэком. Правило закрепляется в `CLAUDE.md`.
- Репозиторий публичный: стандартные раннеры GitHub Actions, включая macOS, для публичных репозиториев бесплатны (сверить в биллинге GitHub перед настройкой CI).

## 4. Вопросы архитектору сверх research §7 и UX «передано архитектору»

1. **Модель конкурентности.** Подтвердить с обоснованием или выключить `SWIFT_APPROACHABLE_CONCURRENCY` и `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`. Отдельно — согласовать настройки тест-таргетов. Это акцент витрины №2 (продукт §1.1), «по умолчанию шаблона» не годится как основание.
2. **Чистое ядро `ChartKit` только на Foundation** (нормализация, деления осей, децимация, агрегация) с тестами на Linux в облаке. Цена: в облачной Ubuntu Swift не предустановлен — нужен setup-скрипт окружения и `swift.org` в Allowed domains.
3. **Шов и источники истории** — по решениям OM-1…3 (`open-meteo-api.md` §7) и открытым вопросам там же, §6.
4. **Атрибуция Open-Meteo (CC BY 4.0)** — в UX уже решена: нижняя строка «Данные: Open-Meteo» на S1, S3 и S4 (UX §4.6). Архитектору — только учесть.
5. **Тесты без сети** — фикстуры ответов API, чтобы агентные сессии и CI не расходовали дневной лимит (`open-meteo-api.md` §5).

## 5. Решения о harness до Harness-1

- **ECC (github.com/affaan-m/ecc) не ставим.** Причины: 28 хуков на каждый шаг расходуют лимиты Pro; автоматическая «память-инстинкты» противоречит правилу «память только с согласия»; хуки рассчитаны на JS/TS; плагины не доходят до облака; конфликты имён `/plan`, `/code-review`.
- **Из ECC берём идеи:**
  - классификатор размера тикета trivial / small / standard / large определяет, какие этапы запускаются (мелкому тикету архитектор и критик не нужны) — вошёл в harness v2 как поле Class: minor / small / standard / large (harness §5);
  - две явные точки ожидания человека (утверждение плана, перед коммитом) — основа точек вызова Edward;
  - Swift-скиллы ECC — только как справочник, не ставятся.
- **Память агентов — только с согласия Edward.** Никаких автоматических записей в память или `CLAUDE.md`.
- **Jira:** только `myweather.atlassian.net`, проект MW. Рабочий сайт не читать и не писать.
