# MW-30: локальные пакеты ChartKit и WeatherCore, изоляция, тесты пакетов в CI и Linux-job

Спека архитектора тикета (harness §5, §6.1). Тикет: https://myweather.atlassian.net/browse/MW-30
(Task, Class standard, Runs on Mac).

## 1. Контекст и цель

Каркас трёх модулей фундамента (A-1): два локальных SPM-пакета в `Packages/`, подключённые к приложению, настройки
изоляции по таблице A-38, SwiftLint на глушители (A-39) и CI: тесты пакетов в обязательном check `test` плюс
Linux-job для `ChartKitCore` (A-41). Кода ядра и домена нет: в каждом таргете одна заготовка, в каждом тест-таргете
один тест-заглушка. На тикете держатся MW-33, MW-34, MW-39.

**Предусловие.** MW-31 (удаление `MyWeatherUITests` и шаблонного SwiftData-кода) правит тот же
`project.pbxproj`. Ветку `MW-30` создавать от `origin/develop` **после merge MW-31**. Если MW-31 ещё не влит —
стоп и вопрос треду тикета, а не ручное слияние `project.pbxproj`.

## 2. Решения

Решения фундамента — `docs/architecture.md`; здесь только то, как они ложатся на этот тикет.

- **D-1. Структура пакетов** — A-1, A-2, A-3, A-40: `Packages/ChartKit` (таргеты `ChartKitCore`, `ChartKit`,
  тест-таргет `ChartKitCoreTests`) и `Packages/WeatherCore` (`WeatherCore`, `WeatherCoreTests`).
  `platforms: [.iOS(.v17), .macOS(.v14)]`, `swiftLanguageModes: [.v6]`, `// swift-tools-version: 6.2`.
  Внешних зависимостей нет. Тест-таргета для `ChartKit` нет: A-40 его не предусматривает.
- **D-2. Граница для Linux в манифесте** — A-41: продукт и таргет `ChartKit` добавляются в `Package.swift` под
  `#if canImport(SwiftUI)`. Исходники `ChartKit` условной компиляцией не оборачиваются.
- **D-3. Изоляция** — A-38. Пакеты: общий набор `swiftSettings` плюс `.defaultIsolation(...)` по таргету.
  Approachable Concurrency в SwiftPM — это upcoming features, которые Xcode включает флагом
  `SWIFT_APPROACHABLE_CONCURRENCY`; часть из них уже входит в языковой режим Swift 6. Ожидаемый набор (эскиз, его
  сверяет исполнитель под Swift 6.4, architecture §12 риск 5):
  - `.enableUpcomingFeature("NonisolatedNonsendingByDefault")`
  - `.enableUpcomingFeature("InferIsolatedConformances")`
  - `.enableUpcomingFeature("MemberImportVisibility")` — **[сам]** не из A-38, а для паритета с приложением
    (`SWIFT_UPCOMING_FEATURE_MEMBER_IMPORT_VISIBILITY = YES` в `project.pbxproj`): без него члены транзитивно
    импортированного модуля видны без своего `import`, и «граница доказывается компилятором» (A-1, A-2) слабеет.
  - `ChartKit` — `.defaultIsolation(MainActor.self)`; `ChartKitCore`, `ChartKitCoreTests`, `WeatherCore`,
    `WeatherCoreTests` — `.defaultIsolation(nil)`. `nil` — значение по умолчанию, но пишется явно: таблица A-38
    читается прямо из манифеста.
- **D-4. Изоляция в проекте Xcode** — A-38: у приложения `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` и
  `SWIFT_APPROACHABLE_CONCURRENCY = YES` уже стоят. У `MyWeatherTests` нет `SWIFT_DEFAULT_ACTOR_ISOLATION` —
  добавить `MainActor` (Debug и Release). Больше build settings не трогать.
- **D-5. Подключение к приложению** — A-1 («приложение — единственный интегратор»): оба пакета — локальные
  зависимости проекта, продукты `ChartKit`, `ChartKitCore`, `WeatherCore` линкуются только в таргет `MyWeather`.
  `MyWeatherTests` их не линкует, `import` в код приложения не добавляется (P3: импортов без использования нет; первый
  `import` придёт с первым кодом пакета). **[сам]** Проект правится гемом `xcodeproj`, как в MW-31 (PR #38):
  исполнитель работает через Remote Control без GUI Xcode, а ручная правка `project.pbxproj` хрупкая.
- **D-8. `.gitignore` в бандле** — **[сам]**, по находке ревьюера PR #38: корневой `.gitignore` стоит в Resources
  build phase таргета `MyWeather` (`project.pbxproj`, `.gitignore in Resources`) и копируется в бандл приложения.
  Убирается из build phase тем же скриптом (ссылка в группе проекта остаётся). Это Chore MW-58, он закрывается
  в PR MW-30: тикет и так правит `project.pbxproj` тем же скриптом, отдельный PR дал бы ещё один конфликт по файлу.
- **D-6. SwiftLint** — A-39. **[сам]** Конфиг `.swiftlint.yml` в корне с `only_rules` из трёх правил и шаг в
  check `test`, `--strict`. Не build-tool plugin в проекте: он требует доверия плагину в Xcode и
  `-skipPackagePluginValidation` в CI, а это внешняя зависимость пакета без нужды (P3). Не отдельный job:
  check `test` уже обязателен в rulesets, отдельный job пришлось бы делать required Edward.
- **D-7. CI** — A-41, harness §5.2 п. 3: шаги `swift test` для обоих пакетов идут в job `test` сразу после
  `Select Xcode`, до симулятора: падают быстро и на том же Xcode, что на Mac. Linux-job `chartkit-linux` в том же
  `ci.yml`, контейнер официального образа Swift. В rulesets **не** добавляется (Границы тикета: required — только
  решением Edward).

**НЕ приводить к «чище»:** не добавлять `@_exported import` (A-2: реэкспорта нет), не выносить `ChartKitCore` в
отдельный пакет (A-41 «Почему не»), не прогонять тесты пакетов через `xcodebuild -scheme` в симуляторе (A-41).

### Шаг 1. `Packages/ChartKit/Package.swift` (целиком)

```swift
// swift-tools-version: 6.2
import PackageDescription

// Approachable Concurrency and import visibility, shared by every target (A-38).
let commonSettings: [SwiftSetting] = [
    .enableUpcomingFeature("NonisolatedNonsendingByDefault"),
    .enableUpcomingFeature("InferIsolatedConformances"),
    .enableUpcomingFeature("MemberImportVisibility"),
]

// Pure algorithms: nonisolated by default (A-38).
let coreSettings: [SwiftSetting] = commonSettings + [.defaultIsolation(nil)]

// SwiftUI layer: main actor by default (A-38).
let uiSettings: [SwiftSetting] = commonSettings + [.defaultIsolation(MainActor.self)]

var products: [Product] = [
    .library(name: "ChartKitCore", targets: ["ChartKitCore"]),
]

var targets: [Target] = [
    .target(name: "ChartKitCore", swiftSettings: coreSettings),
    .testTarget(name: "ChartKitCoreTests", dependencies: ["ChartKitCore"], swiftSettings: coreSettings),
]

// ChartKit needs SwiftUI and Charts. The manifest is evaluated on the host, so on Linux
// the package contains only ChartKitCore and its tests (A-41).
#if canImport(SwiftUI)
products.append(.library(name: "ChartKit", targets: ["ChartKit"]))
targets.append(.target(name: "ChartKit", dependencies: ["ChartKitCore"], swiftSettings: uiSettings))
#endif

let package = Package(
    name: "ChartKit",
    platforms: [.iOS(.v17), .macOS(.v14)],
    products: products,
    targets: targets,
    swiftLanguageModes: [.v6]
)
```

### Шаг 5. Проект Xcode (гем `xcodeproj`, как в MW-31)

Гем уже стоит на Mac (MW-31 работал на 1.27.0): `gem list xcodeproj`. Скрипт запускать из корня worktree,
сам скрипт в репозиторий не коммитится (держать вне worktree, например `/tmp/mw30_project.rb`):

```ruby
require 'xcodeproj'

project = Xcodeproj::Project.open('MyWeather.xcodeproj')
app = project.targets.find { |t| t.name == 'MyWeather' } or abort 'no MyWeather target'
tests = project.targets.find { |t| t.name == 'MyWeatherTests' } or abort 'no MyWeatherTests target'

# A-1, D-5: local packages, products linked into the app target only.
{
  'Packages/ChartKit' => %w[ChartKit ChartKitCore],
  'Packages/WeatherCore' => %w[WeatherCore],
}.each do |path, products|
  ref = project.new(Xcodeproj::Project::Object::XCLocalSwiftPackageReference)
  ref.relative_path = path
  project.root_object.package_references << ref

  products.each do |name|
    dep = project.new(Xcodeproj::Project::Object::XCSwiftPackageProductDependency)
    dep.product_name = name
    app.package_product_dependencies << dep

    build_file = project.new(Xcodeproj::Project::Object::PBXBuildFile)
    build_file.product_ref = dep
    app.frameworks_build_phase.files << build_file
  end
end

# A-38, D-4: test target runs on the main actor by default, like the app.
tests.build_configurations.each do |config|
  config.build_settings['SWIFT_DEFAULT_ACTOR_ISOLATION'] = 'MainActor'
end

# D-8: the root .gitignore must not be copied into the app bundle.
app.resources_build_phase.files
   .select { |bf| bf.file_ref && bf.file_ref.path == '.gitignore' }
   .each(&:remove_from_project)

project.save
```

Проверка сразу после скрипта:

```sh
plutil -lint MyWeather.xcodeproj/project.pbxproj
xcodebuild -list -project MyWeather.xcodeproj
grep -c "XCLocalSwiftPackageReference \"Packages/" MyWeather.xcodeproj/project.pbxproj   # ожидается > 0
grep -n "gitignore in Resources" MyWeather.xcodeproj/project.pbxproj                    # ожидается пусто
```

Ожидаемый дифф `project.pbxproj`:
- секция `XCLocalSwiftPackageReference` с двумя записями (`relativePath = Packages/ChartKit;`,
  `relativePath = Packages/WeatherCore;`) и `packageReferences` в `PBXProject`;
- секция `XCSwiftPackageProductDependency` с тремя записями (`productName = ChartKit;` и т. д.); у таргета
  `MyWeather` `packageProductDependencies` снова непустой (MW-31 оставил его пустым);
- три `PBXBuildFile` `… in Frameworks` с `productRef` во frameworks build phase таргета `MyWeather`;
- `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor;` в Debug и Release `MyWeatherTests`;
- удалены `PBXBuildFile` `.gitignore in Resources` и его строка в Resources build phase; `PBXFileReference`
  `.gitignore` и строка в главной группе остаются.

Гем пишет файл не так, как Xcode (ревьюер PR #38): возможны переформатирование, пустые `exceptions = ( );`,
другой порядок ключей. Это допустимо, но изменения проекта идут **отдельным коммитом**
`MW-30: link local packages in Xcode project`, без других файлов. Если после `xcodebuild` (§8) `git status`
снова показывает `project.pbxproj` изменённым — это нормализация, ещё один отдельный коммит
`MW-30: normalize project file`, с описанием в отчёте. Смена `objectVersion` или `LastUpgradeCheck` — откатить
и назвать в отчёте.

Если гем не принимает `XCLocalSwiftPackageReference` или `xcodebuild` после скрипта не видит пакеты (`Missing
package product`) — первый фолбэк: добавить `dep.package = ref` для каждого продукта; не помогло — стоп и вопрос
треду тикета, `project.pbxproj` руками не править.

## 5. Сценарии и краевые случаи

- **Upcoming feature уже включена языковым режимом** (компилятор пишет, что фича «already enabled» или неизвестна):
  убрать её из набора, в A-38 записать фактический набор, в отчёте — текст предупреждения.
- **`.defaultIsolation(nil)` не принимается** (тип параметра в 6.4 иной): убрать строку у nonisolated-таргетов
  (nonisolated — значение по умолчанию), в A-38 записать это, в отчёте — текст ошибки.
- **`swiftlint` нет на Mac**: не ставить; проверка — в CI, в отчёте «локально не прогонялся».
- **SwiftLint находит нарушения в существующем коде** (после MW-31): чинить в этом же PR, если правка локальная;
  если нет — стоп и вопрос треду тикета.
- **Linux-job красный из-за образа** (нет тега, нет Swift Testing): не ослаблять тест; отчёт с логом треду тикета.
- **Xcode после добавления пакетов не собирает приложение** из-за `platforms` (macOS 14 для пакета не мешает iOS
  17 приложения — так и должно быть): ошибка в отчёт, `platforms` не менять без треда тикета.
