# MW-39: WeatherCore — Metric, клиент Open-Meteo, URL запросов, разбор в HourlyGrid

Спека архитектора тикета (harness §5, §6.1). Правки по критике круга 1 (K-1…K-7, `/mnt/project-files/MW-39/critic.md`) внесены в текст. Тикет: https://myweather.atlassian.net/browse/MW-39
(Task, Class standard, Runs on Mac, эпик MW-26).

## 1. Контекст и цель

Первый код `WeatherCore`: граница данных (A-20). Выше клиента ходят только доменные типы, DTO из файла разбора не
выходят (P7). Время — абсолютная UTC-сетка с шагом 3600 с плюс пояс локации (A-22, продукт §2.5, §6.2). На тикете
держатся MW-40 (шов истории), MW-41 (агрегации), MW-42 (поиск города), MW-43/44 (кэш), MW-46 (репозиторий).

**Предусловия.**
- MW-30 (пакеты) и MW-32 (фикстуры) влиты в `develop`.
- **MW-60 (PR #41) влит в `develop`.** Спека опирается на A-22 в редакции MW-60: правая граница Archive —
  по сегодня локации **и** сегодня UTC, Historical Forecast — по сегодня локации. Если на шаге 0 в
  `docs/architecture.md` ветки `origin/develop` нет строки «**Archive** — `min(конец + 1 сутки, сегодня локации,
  сегодня UTC)`» — стоп и вопрос треду тикета.

## 2. Решения

Решения фундамента — `docs/architecture.md`; здесь то, как они ложатся на тикет. Пометки: **[сам]** — решено
архитектором тикета, критик может оспорить.

- **D-1. `Metric`** — A-47, продукт §2.2, UX §5.1. `public enum Metric: String, CaseIterable, Sendable` — 11 случаев
  **в порядке таблицы продукта §2.2** (это же порядок переменных в запросе и в фикстурах). Порядок чипсов UX §5.1 —
  отдельный явный список `chipOrder`, а не порядок `allCases`: у них разные источники истины, и перестановка чипсов
  не должна менять URL. **[сам]**
- **D-2. Единицы** — A-46, продукт §7.1. `siUnit` — `public enum MetricUnit: Sendable { celsius, percent,
  millimeters, metersPerSecond, degrees, hectopascals, dimensionless }`. Это метка единицы хранения, не
  `Foundation.Unit`: процент и УФ-индекс не размерности, а конвертация с `Measurement` — MW-41 (A-46). **[сам]**
- **D-3. `HourlyGrid`** — A-20, A-22, продукт §6.2. Хранение — плотные `[Float]` на метрику, `null` из ответа
  хранится как `Float.nan` (A-20: «`Float.nan` в хранении»); наружу — только `Float?` через `value(_:at:)`
  («`nil` в домене»). Массив `values` — `package`: кэш (MW-43) пишет его блобом без перекодирования, приложение NaN
  не видит. Метки времени не хранятся: `date(at:) = start + i·3600`. **[сам: A-20 + продукт §6.2]**
- **D-4. Правая граница дат — чистая функция, сборщик URL даты не трогает.** A-22 (MW-60): «обрезку и выброс
  пустого куска делает `fetchPlan` (A-32), а не сборщик URL». Правило живёт в чистой функции
  `HistorySource.latestEndDate(now:timeZone:)` с тестами Окленда и Нью-Йорка; её зовёт `fetchPlan` (MW-44).
  Сборщик запроса и клиент берут даты как есть, без `now` и пояса: молчаливая обрезка в сборщике спрятала бы ошибку
  плана — план считал бы покрытым день, которого не запрашивал (A-30, A-32, P10). Запас «+1 сутки» — тоже
  `fetchPlan`. «Как проверяется» A-22 («тест сборки URL с подменным `now`») — поправка в шаге 9.
  **[сам: A-22, A-32; критик K-1, вариант (а)]**
- **D-5. Ошибки** — A-20. `public enum WeatherError: Error, Sendable, Equatable`:
  `network` (транспорт упал, HTTP 5xx), `rateLimited` (HTTP 429), `rejected(statusCode: Int)` (прочие 4xx — API
  отверг запрос, это ошибка нашего кода, а не сети), `decoding` (тело не разбирается или не сходится с контрактом),
  `noData` (пустая сетка: `hourly.time = []`). Без `String` (A-20). `rejected` расширяет перечень
  A-20 («сеть, лимит, разбор, нет данных»): 400 от Archive (`end_date` вне диапазона, API §6 п. 9) — не «разбор» и
  не «сеть»; смешать — потерять различимость при диагностике. Запись в A-20 — шаг 9. **[сам]**
- **D-6. Отмена не ошибка.** Методы клиента — `async throws` **без** typed throws: бросают `WeatherError` или
  `CancellationError`. Typed `throws(WeatherError)` заставил бы превратить отмену задачи (склейка запросов A-34
  отменяет лишние) в `.network`, и страница показала бы ошибку на отменённой загрузке. `URLError(.cancelled)` из
  транспорта → `CancellationError`. Синхронные функции разбора — `throws(WeatherError)`: отмены в них нет. **[сам]**
- **D-7. Изоляция** — A-38. Пакет `nonisolated` по умолчанию (MW-30). Синхронный разбор — `package` функции
  `OpenMeteoDecoding.decodeForecast(_:)` и соседние: их видят тесты, не приложение. Уход с актора вызывающего —
  `@concurrent package static func` поверх них; клиент ждёт их через `await`. Новых `@MainActor`, `actor`,
  глушителей A-39 нет.
- **D-8. Видимость.** `public`: `Metric`, `MetricUnit`, `HourlyGrid` (+ `value`, `date`, `start`, `count`,
  `metrics`), `Forecast`, `ForecastDay`, `LocalDate`, `Coordinate`, `WeatherError`, `HTTPTransport`, `OpenMeteoClient` (тип и
  `init` — приложение собирает его с транспортом на `URLSession` и отдаёт репозиторию, MW-46/48). Методы клиента,
  `OpenMeteoRequest`, `HistorySource`, `ArchiveData`, `SunDay`, разбор — `package`: их потребители
  внутри пакета (репозиторий, шов, кэш). DTO — `private` в файле разбора. Расширять видимость — тикету-потребителю.
  **[сам: P3, P7]**
- **D-9. DTO — одна форма на все ответы.** `{ timezone: String?, utc_offset_seconds: Int?, hourly:
  [String: [Double?]]?, daily: [String: [Double?]]? }`: колонки — по `apiName`, `time`, `sunrise`, `sunset` —
  unix-секунды (в `Double` точны до 2^53). Одна форма вместо трёх: ответы различаются только набором колонок, а набор проверяет разбор. `*_units`
  не читаются: единицы задаёт запрос (A-21), тест URL это фиксирует. **[сам: P3]**
- **D-10. Geocoding без общих параметров.** A-21 «каждый запрос несёт `timezone=auto`, `wind_speed_unit=ms`,
  `timeformat=unixtime`» относится к погодным запросам: у Geocoding этих параметров нет, эталон MW-32
  (`geocoding-*` в `manifest.json`) записан без них. `count=10` — как в эталоне. Здесь только сборка URL поиска;
  разбор ответа и метод клиента — MW-42 (A-27). Уточнение в A-21 — шаг 9. **[сам: API §1, MW-32]**
- **D-11. Координаты в URL** — не `description` `Double` (даёт `1e-05`), а до 4 знаков после точки, без группировки,
  `en_US_POSIX`: `52.52`, `-74.006`, `174.7633` — как в эталоне. 4 знака ≈ 11 м, сетка IFS 9 км (A-31). **[сам]**
- **D-12. Тесты сверяют URL с эталоном по смыслу, а не строкой.** Эталон `manifest.json` записан Python, он кодирует
  запятую как `%2C`; `URLComponents` запятую в query не кодирует. Сравниваются хост, путь и словарь
  `имя → значение` раскодированных query items (порядок параметров не важен, порядок переменных внутри `hourly` —
  важен). **[сам]**

- **D-13. Сутки `daily` — метка `LocalDate`, а не момент.** `daily.time` — полночь по **одному смещению ответа**
  (`utc_offset_seconds`), а не местная полночь: в `archive-berlin-year` (смещение 3600) с 31.03 по 26.10 это 01:00
  CEST, в `archive-newyork-dst` (−18000) 30.10…02.11 — 01:00 EDT. Потребитель, режущий часы по такому моменту,
  ошибся бы на час, а `LocalDate(момент, in: пояс)` при смещении вперёд дал бы вчера. Поэтому у `ForecastDay` и
  `SunDay` — `date: LocalDate` = UTC-дата момента `daily.time + utc_offset_seconds`; момента начала суток в домене
  нет. Нет `utc_offset_seconds` при непустом `daily` → `.decoding`. Факт — в API §6 п. 8 (шаг 9). **[сам: критик K-2]**

**НЕ «чинить»:**
- не добавлять `models=best_match` в прогноз (A-21: `models` не передаётся) и `models` в Historical Forecast;
- не запрашивать `weather_code`, `is_day` в истории (A-21);
- не делать `Metric.allCases` в порядке чипсов (D-1);
- не превращать `CancellationError` в `WeatherError` (D-6);
- не добавлять `URLSession` в пакет, даже как транспорт по умолчанию (A-20).

### Шаг 2. `Domain/HourlyGrid.swift`

```swift
public struct HourlyGrid: Sendable, Equatable {
    public static let step: TimeInterval = 3600
    public let start: Date              // absolute instant of index 0; not necessarily a whole UTC hour (+05:30)
    public let count: Int
    package let values: [Metric: [Float]]   // NaN = no value (D-3); every array has `count` elements

    /// Throws `.decoding` if any array's length differs from `count`, or `count < 0`.
    package init(start: Date, count: Int, values: [Metric: [Float]]) throws(WeatherError)

    public var metrics: Set<Metric> { Set(values.keys) }
    public func date(at index: Int) -> Date            // start + index * step
    /// nil: metric not in this grid, index out of 0..<count, or the stored value is NaN (null in the response).
    public func value(_ metric: Metric, at index: Int) -> Float?
}
```

`Equatable` синтезированный сравнивает NaN как неравные: реализовать `==` вручную — равны `start`, `count`,
ключи, и поэлементно значения, где NaN == NaN (`a == b || (a.isNaN && b.isNaN)`).

### Шаг 3. `Domain/Forecast.swift`, `Domain/ArchiveData.swift`

```swift

    public let isDay: [Bool?]              // aligned with hourly indices
```

```swift
package struct ArchiveData: Sendable, Equatable {
    package let hourly: HourlyGrid         // 9 metrics: Metric.allCases without precipitationProbability, uvIndex
```

`init` у всех — memberwise с видимостью `package` (снаружи их не создают). Полярный день (Мурманск, июнь) приходит

`ForecastDay.date` публичен, поэтому `LocalDate` — `public` (тип, поля, `init(year:month:day:)`, `iso8601`,
`Comparable`); `init(_:in:)` — тоже `public`: приложению «сегодня локации» нужно для сопоставления с `days`.

### Шаг 6. `Network/OpenMeteoRequest.swift`

```swift
package enum HistorySource: Sendable, Hashable {
    case archive        // Archive API, 9 metrics
    case historicalUV   // Historical Forecast API, uv_index

    /// Latest `end_date` the source accepts (A-22, MW-60):
    /// archive      — min(today in `timeZone`, today in UTC)  (Archive counts "today" in UTC, API §6 п. 9)
    /// historicalUV — today in `timeZone`
    /// The "+1 day" margin at plan edges is fetchPlan's job (A-32), not this function's.
    package func latestEndDate(now: Date, timeZone: TimeZone) -> LocalDate
}

package enum SearchLanguage: String, Sendable { case ru, en }

package struct OpenMeteoRequest: Sendable, Hashable {
    package let url: URL
    private init(url: URL)

    package static func forecast(at coordinate: Coordinate) -> OpenMeteoRequest
    /// Dates are used as given: clamping to `latestEndDate` is fetchPlan's job (D-4, A-22).
    package static func history(_ source: HistorySource, at coordinate: Coordinate,
                                dates: ClosedRange<LocalDate>) -> OpenMeteoRequest
    package static func search(name: String, language: SearchLanguage) -> OpenMeteoRequest
}
```

Таблица запросов (A-21; хосты и пути — API §1, эталон `manifest.json`). Переменные — через запятую, в порядке
`Metric.allCases` и затем как в таблице.

| Запрос | URL до `?` | Параметры |
|---|---|---|
| `forecast` | `https://api.open-meteo.com/v1/forecast` | `latitude`, `longitude`, `forecast_days=16`, `hourly=` 11 × `apiName` + `weather_code,is_day`, `daily=weather_code,sunrise,sunset,temperature_2m_max,temperature_2m_min`, общие три |
| `history(.archive)` | `https://archive-api.open-meteo.com/v1/archive` | `latitude`, `longitude`, `start_date`, `end_date`, `models=ecmwf_ifs`, `hourly=` 9 × `apiName` (без `precipitation_probability`, `uv_index`), `daily=sunrise,sunset`, общие три |
| `history(.historicalUV)` | `https://historical-forecast-api.open-meteo.com/v1/forecast` | `latitude`, `longitude`, `start_date`, `end_date`, `hourly=uv_index`, общие три |
| `search` | `https://geocoding-api.open-meteo.com/v1/search` | `name`, `language`, `count=10` (D-10: без общих трёх) |

Общие три: `timezone=auto`, `wind_speed_unit=ms`, `timeformat=unixtime`. Больше параметров нет: ни `past_days`, ни
`current`, ни `models` у прогноза и Historical Forecast, ни прочих единиц.

Списки переменных — `package static let` рядом со сборкой (`forecastHourly: [Metric] = Metric.allCases`,
`archiveHourly: [Metric]` — `allCases` без двух), чтобы MW-40 и разбор брали тот же набор, а не копию.

Сборка — `URLComponents` с `queryItems`; `start_date`/`end_date` — `LocalDate.iso8601`. Координаты — D-11:
`value.formatted(.number.precision(.fractionLength(0...4)).grouping(.never).locale(Locale(identifier: "en_US_POSIX")))`.
Плюс в query: `URLComponents` оставляет `+` как есть, а сервер читает его как пробел — после сборки
`percentEncodedQuery` заменить `+` на `%2B` (касается только `name` поиска). `components.url == nil` при
фиксированных схеме, хосте и пути невозможен: `guard let … else { preconditionFailure("…") }`, не force unwrap (A-39).

### Шаг 7. `Network/OpenMeteoDecoding.swift`

```swift
private struct ResponseDTO: Decodable {            // D-9; never leaves this file
    let timezone: String?
    let utc_offset_seconds: Int?                   // or CodingKeys; needed for daily labels (D-13)
    let hourly: [String: [Double?]]?
    let daily: [String: [Double?]]?
}

package enum OpenMeteoDecoding {
    package static func decodeForecast(_ data: Data) throws(WeatherError) -> Forecast
    package static func decodeArchive(_ data: Data) throws(WeatherError) -> ArchiveData
    package static func decodeHistoricalUV(_ data: Data) throws(WeatherError) -> HourlyGrid

    @concurrent package static func forecast(from data: Data) async throws(WeatherError) -> Forecast
    @concurrent package static func archive(from data: Data) async throws(WeatherError) -> ArchiveData
    @concurrent package static func historicalUV(from data: Data) async throws(WeatherError) -> HourlyGrid
}
```

`@concurrent`-обёртки только вызывают синхронную пару (A-38: одна точка ухода с актора).

Правила разбора — общие для трёх ответов, по порядку:

1. `JSONDecoder` падает → `.decoding`.
2. `timezone` отсутствует или `TimeZone(identifier:)` даёт `nil` → `.decoding` (проверяется во всех трёх ответах:
   ответ без пояса — не тот контракт; в домен он идёт только у `Forecast`).
3. `hourly.time` отсутствует → `.decoding`; пуст → `.noData`.
4. Каждый соседний шаг `time` ровно 3600 с, иначе `.decoding` (сетка равномерна по построению, A-22; сдвиг не на
   целый час — ошибка разбора, A-23). Начало на целом часе UTC **не** требуется (Мумбаи 18:30Z).
5. Каждая ожидаемая колонка присутствует и её длина равна длине `time`, иначе `.decoding`. Ожидаемые колонки —
   ровно те, что запрошены (шаг 6): прогноз — 11 метрик + `weather_code`, `is_day`; архив — 9 метрик; УФ —
   `uv_index`. Лишние колонки игнорируются.
6. Значения метрик: `Double?` → `Float`, `nil` → `.nan`.
7. `weather_code`: `nil` → `nil`, иначе `Int(exactly:)`; не целое → `.decoding`. `is_day`: `0` → `false`, `1` →
   `true`, `nil` → `nil`, прочее → `.decoding`.
8. `daily` (прогноз, архив): ключа `daily` нет → `.decoding` (колонки запрошены); `daily.time = []` → пустой
   массив дней. `daily.time` и ожидаемые колонки (`weather_code`, `sunrise`, `sunset`, `temperature_2m_max`,
   `temperature_2m_min` / `sunrise`, `sunset`) одной длины, иначе `.decoding`. Шаг `daily.time` **не** проверяется.
   Метка суток — D-13: `LocalDate(Date(timeIntervalSince1970: time + utc_offset_seconds), in: .gmt)`; нет
   `utc_offset_seconds` при непустом `daily.time` → `.decoding`. `sunrise`/`sunset` → `Date(timeIntervalSince1970:)`,
   `nil` → `nil`.
9. `HourlyGrid(start: Date(timeIntervalSince1970: time[0]), count: time.count, values:)`.

| Что пришло от транспорта | Результат |

| бросил `CancellationError` | пробросить как есть |
| бросил `URLError` с кодом `.cancelled` | `throw CancellationError()` |
| бросил что-то другое | `WeatherError.network` |
| статус 200…299 | тело |
| 429 | `WeatherError.rateLimited` |
| прочие 400…499 | `WeatherError.rejected(statusCode:)` |
| прочее (5xx, 1xx, 3xx) | `WeatherError.network` |

Тело ответа с ошибкой (`{"error": true, "reason": …}`) не разбирается: строки в домен не идут (A-20).

## 5. Сценарии и краевые случаи

- **`null` в хвосте прогноза** (последние часы 16-х суток: у Окленда, Токио, Мурманска — почти все колонки, у
  Берлина — только `precipitation_probability`; в `daily` — последний день) → `nil`, сетка и дни той же длины.
- **Пояс `+05:30`** — `start` не на целом часе UTC, шаг всё равно 3600.
- **Переход на летнее время** — сетка в UTC не замечает перехода; местные сутки содержат 23 или 25 элементов.
- **Восточнее UTC до смены суток UTC** (Окленд утром) — `latestEndDate` Archive = вчера местного, Historical
  Forecast — местное «сегодня». Сборщик даты не обрезает (D-4).
- **Западнее UTC вечером** (Нью-Йорк, в UTC уже завтра) — обе границы = сегодня локации.
- **Сутки `daily` при летнем времени** — метка `LocalDate` по смещению ответа, а не местная полночь (D-13).
- **429** → `.rateLimited`; **400** от Archive → `.rejected(statusCode: 400)`; **503** → `.network`.
- **Офлайн** (`URLError(.notConnectedToInternet)`) → `.network`. **Отмена** → `CancellationError`.
- **Пустой ответ** (`hourly.time = []`) → `.noData`. **Битое тело** → `.decoding`.
- **Название города с `+`, `&`, `=`, пробелом, кириллицей** — кодируются, `+` → `%2B`.
