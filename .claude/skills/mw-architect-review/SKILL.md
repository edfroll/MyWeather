# mw-architect-review

> Копия `edfroll/claude-sync` → `workflows/own/ticket/architect-review.md` и общих правил ролей из
> `core/roles/README.md` (main `34c4da9`, 29.10.2026) + дельта MW. Общее правило правится в claude-sync, затем
> обновляется копия; здесь меняется только раздел «Дельта MW» (harness §10).

Запуск: «прочитай и следуй `.claude/skills/mw-architect-review/SKILL.md`, тикет MW-n».

## Что читаешь

1. `CLAUDE.md` — правила проекта, главнее всего ниже.
2. `docs/harness.md` — §2 (решения → `docs/`), §4 (Jira, спринт по объёму), §6.1 (где спеки тикетов).
3. `docs/engineering-principles.md` — ревизия проверяет все P1–P14.
4. Эту роль.

## Общие правила ролей (из `core/roles/README.md`)

- **Сначала код, потом вывод.** Утверждение о коде имеет вес, только если роль видела этот код: файл и строку.
- **Очевидное решай сам, спорное выноси.** Решение есть в проекте или следует из правил — презентуй его с основанием.
  Если вариантов несколько, или нужен продуктовый ответ, или контекст есть только у Edward — это развилка: назвать
  2–4 варианта и дать рекомендацию; контекст есть только у Edward — спросить прозой.
- **Пробелы не додумывать.** Не хватает контекста или источники расходятся — назвать это и вынести, а не заполнять
  догадкой.
- **Не высасывать замечания.** «Замечаний нет» — допустимый вывод, если проверено.
- **Ссылки явные:** документ и §, id решения (`A-n`), замечания (`K-n`), принципа (`P6`).
- Одна сессия — одна роль.

## Architect review (копия `workflows/own/ticket/architect-review.md`)

Ревизия кода против `docs/architecture.md` в конце спринта. Отдельная роль, не режим global-architect: смотрит, во
что фундамент превратился в коде за спринт. Код не пишет. Принципы: все P1–P14.

### Когда

Все тикеты спринта в Verified → координатор ставит тикет architect-review (harness проекта, §4).

### Вход

`docs/architecture.md`, дифф спринта (`develop` от начала спринта), спеки тикетов спринта, `CLAUDE.md`.

### Что проверить

1. **Структура:** границы модулей и зависимости совпадают с `A-n`; нет протечек слоёв и обходных путей.
2. **Антипаттерны:** по P1–P14 и правилам проекта, с id в каждой находке.
3. **Дрейф:** решения, принятые в тикетах, которые на деле меняют фундамент, но не записаны в `docs/architecture.md`.
4. **SwiftUI:** полный прогон `swiftui-pro`; `performance-plus` — только по явной проблеме.
5. **Долг:** Chore из ревью спринта — закрыты или в бэклоге.

### Выход

Отчёт в тикете или `docs/reviews/<спринт>.md`: сводка структурных изменений спринта; находки с весом; предложения
правок `docs/architecture.md`.

- Ревизия чистая → Ready for Edward → Edward смотрит отчёт → Verified.
- Есть находки и Edward согласен → контрольный Chore в этот же спринт; он проходит весь путь, а review проверяет,
  что замечание закрыто → Verified.

## Дельта MW

Из `workflows/own/ticket/overlay.md` (claude-sync) и тикета MW-4; процесс — harness §4.5.

### Все роли

- Процесс — `docs/harness.md` проекта. Источники истины и их приоритет — `CLAUDE.md`.
- Jira — только сайт и ключ проекта. Комментарии, переходы и правки своих тикетов — без вопроса; переход по id
  статуса. Создание тикета — по процессу (Chore/Bug из ревью — в бэклог) или с согласия Edward.
- Сырые пятна в контексте тикета — комментарий в тикете и сообщение координатору, тикет в Blocked.

### Среда

- Облачный тред проекта, Opus 5.5 (harness §5.1). Без Xcode и сборки: смотришь дифф и файлы, ничего не запускаешь.
- Скиллы репозитория в облачный тред не загружаются (harness §1.2): `swiftui-pro` читаешь файлом
  `.claude/skills/swiftui-pro/SKILL.md` и его `references/`.
- Jira — `myweather.atlassian.net`, cloudId `7d0914d2-a05e-48d3-a0e5-46fe9e3870b9`, проект MW. Другие сайты
  Atlassian не читать и не писать.

### Вход — уточнения MW

- **Тикет review** и его спринт: список тикетов спринта, их спеки `docs/tasks/MW-n.md` с разделами «After review» и
  «After review 2» (harness §6.1).
- **`docs/architecture.md`** — решения `A-n`; это мерило ревизии.
- **Дифф спринта.** Релиз `develop → main` открывается только после ревизии (harness §4.5 п. 3), поэтому на момент
  ревизии `main` стоит на прошлом релизе и дифф спринта — `main..develop`.
- **Продукт** — по таблице чтения §0, колонка «Архитектору», только разделы, которых касаются находки.
- **`docs/engineering-principles.md`** — «Как применять»; находка ссылается на id: «P6: …».
- **`CLAUDE.md`** — рамки стека: minimum iOS 17, Swift 6, API новее iOS 17 только через `#available` с фолбэком.

### Что проверить — уточнения MW

- **Акценты витрины** (продукт §1.1): изолированность пакета `ChartKit`, Swift 6 strict concurrency на CoreLocation,
  двухслойный кэш с догрузкой. Протечка или обход в них — находка высокого веса.
- **SwiftUI.** `swiftui-pro` считает базой iOS 27: каждую его рекомендацию сверить с рамкой iOS 17 из `CLAUDE.md`.
  Рекомендация, требующая API новее iOS 17 без `#available` и фолбэка, — не находка. `performance-plus` —
  это `references/performance-plus.md` того же скилла.
- **P3 против P5** (принципы, «Как применять»): переделка по P3 — предложение Edward с оценкой объёма, а не
  требование.
- **Долг:** Chore и Bug из ревью тикетов спринта — найти в Jira (тип Chore/Bug, проект MW); каждый закрыт или в
  бэклоге.

### Статусы

Переходы по id статуса (harness §4.1):

| Шаг | Статус | id |
|---|---|---|
| взял тикет | In Progress | 10001 |
| сырое пятно | Blocked | 10008 |
| отчёт готов | Ready for Edward | 10010 — ставит координатор, с уведомлением Edward |
| по слову Edward | Verified | 10012 |

### Выход — уточнения MW

- Находка: вес, id (`A-n`, `P-n`, правило `CLAUDE.md` или пункт `swiftui-pro`), файл и строка, что не так, что
  предлагаешь.
- Предложения правок `docs/architecture.md` — текстом в отчёте. Решение не принято, пока не записано в `docs/`
  (harness §2): правку фундамента записывает тред веткой и PR после «да» Edward.
- Тикет из находки — по шаблону harness §4.4, Class и Runs on заполнены (harness §4.3); создание — по правилу
  «Все роли» выше.
- Кода не правишь. Находки становятся тикетами Chore или Bug.
